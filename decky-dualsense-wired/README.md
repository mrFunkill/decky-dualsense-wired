# DualSense Wired

**Русский** · [English](README.en.md)

Плагин для [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader): DualSense / DualSense Edge,
подключённый к Steam Deck по Bluetooth, работает в Steam и играх так же, как подключённый кабелем, —
вместе со звуком из динамика геймпада и HD-вибрацией в играх, которые их поддерживают.

Проверено на Steam Deck (SteamOS, Proton 11): Marvel's Spider-Man Remastered, Miles Morales,
Helldivers 2 — динамик, HD-вибрация и адаптивные триггеры работают без настройки под игру.

## Возможности

- **Проводной режим по Bluetooth.** Игры и Steam видят USB DualSense: адаптивные триггеры,
  подсветка, гироскоп, тачпад, кнопка PS работают как по кабелю.
- **Звук игр на контроллер** (включено по умолчанию). Всё, что игра выводит в динамик DualSense
  и на HD-вибрацию, передаётся в геймпад по Bluetooth — как на ПК при подключении кабелем.
- **Весь звук Deck на контроллер** (выключено по умолчанию). Вместо звука игр в динамик геймпада
  идёт весь звук Deck, а вибрация вычисляется из него — режим для игр без поддержки DualSense.
- **Наушники в разъёме геймпада**: когда они подключены, звук идёт в них, а не в динамик.
- **Микрофон геймпада** (выключен по умолчанию): микрофон геймпада или гарнитуры в нём доступен
  Steam, Discord и играм. Кнопка mute на геймпаде выключает микрофон, её индикатор горит.
- **Быстрые триггеры**: эффекты триггеров и подсветка отправляются сразу, а не вместе со звуком.
- Громкость динамика, сила вибрации и буфер звука (задержка / устойчивость к помехам)
  настраиваются в панели плагина.
- **Тест геймпада** — страница из панели плагина: кнопки, стики, гироскоп, тачпад, вибрация,
  адаптивные триггеры, подсветка, тестовые звуки и HD-вибрация, уровень и запись микрофона.
  Всё проверяется через виртуальный контроллер, как в игре.
- **Обновления**: кнопка «Проверить обновления» в панели — плагин сам скачает и поставит новую
  версию с GitHub.
- Переподключение геймпада во время игры не сбрасывает звук и триггеры: виртуальный контроллер
  ждёт возвращения геймпада 2 минуты.
- Заряд геймпада — в панели плагина и уведомлением Steam при 20% и 10%: Steam показывает заряд
  в верхней строке только для беспроводных геймпадов, а этот для него проводной.
- Панель плагина на английском, а при русском интерфейсе Steam — на русском.

Нужно, чтобы для игры был **выключен Steam Input** (иначе игра видит контроллер Xbox).

## Установка

Нужен установленный [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader).

1. В Decky: ⚙ **Настройки → Общие** → включите **Режим разработчика** (Developer mode).
2. На появившейся вкладке **Разработчик** (Developer) выберите **Установить плагин по URL**
   (Install Plugin from URL) и вставьте ссылку
   на архив из [последнего релиза](https://github.com/mrFunkill/decky-dualsense-wired/releases/latest), например:
   `https://github.com/mrFunkill/decky-dualsense-wired/releases/download/v0.5.3/decky-dualsense-wired-v0.5.3.zip`.
   Либо скачайте архив на Deck и выберите **Установить плагин из ZIP-файла** (Install Plugin from ZIP File).
3. Подтвердите установку. Плагин работает от root — это нужно для виртуального USB-контроллера.
4. Подключите DualSense по Bluetooth. В свойствах игры **выключите Steam Input**.

Удаляется плагин штатно через Decky: он сам вернёт геймпад Steam и уберёт свою службу из
префиксов Proton.

## Как это устроено

Бэкенд (`main.py`, `py_modules/`) работает от root (флаг `root` в `plugin.json`).

1. **Виртуальный USB-контроллер** (`dualsense_gadget_bridge.py`, `dualsense_gadget.py`). Каждый
   DualSense по Bluetooth выставляется как USB-устройство: USB-гаджет (configfs, `f_hid`) на виртуальной
   шине ядра `dummy_hcd`, с HID на интерфейсе 3, как у настоящего DualSense. Отчёты переводятся между
   форматами Bluetooth (`0x31`) и USB (`0x01`/`0x02`), служебные запросы пересылаются геймпаду.
2. **Аудиоустройство контроллера.** Рядом создаётся 4-канальный выход PipeWire `dualsense_gadget_<порт>`,
   привязанный к тому же USB-устройству (`sysfs.path`), поэтому Wine выдаёт ему и HID общий Container ID.
   Каналы 1–2 — динамик/наушники, 3–4 — два вибромотора, как у проводного DualSense.
3. **Служба в префиксах Proton** (`proton_prefixes.py`, `bin/dualsense_wired_helper.exe`, исходник —
   `native/helper`). Игры находят звуковое устройство контроллера через узлы
   `SWD\MMDEVAPI\…` с общим Container ID, которых Wine не создаёт. Служба создаёт их при запуске
   префикса. Плагин раз в минуту устанавливает её во все префиксы Proton, которые сейчас не запущены.
4. **Передача в геймпад** (`dualsense_audio.py`). Звук захватывается из выхода, кодируется в Opus,
   вибрация передаётся с частотой 3 кГц — в расширенных Bluetooth-отчётах DualSense (`0x36`/`0x39`),
   описанных в `research/FINDINGS.md`. Отчёты игры (триггеры, подсветка) идут отдельными отчётами
   между звуковыми. Пока звука нет, поток не отправляется: Bluetooth на Deck делит радио с Wi-Fi,
   и при перегрузке канала BlueZ отключает устройство ввода.
5. **Микрофон** (`dualsense_mic.py`). Геймпад присылает голос кадрами Opus в отдельных входных
   отчётах; плагин декодирует их в источник PipeWire `dualsense_mic_<порт>`, привязанный к тому же
   USB-устройству, что и выход.

Поля потока (длина буфера, флаг микрофона), разъём наушников и формат голосовых отчётов узнаны из
открытого проекта [DS5Dongle](https://github.com/awalol/DS5Dongle) (MIT); код написан независимо.

Каждый DualSense по Bluetooth получает свой виртуальный USB-порт (`dummy_hcd` загружается с
`num=4`): своя шина, свой Container ID и свой выход `dualsense_gadget_<порт>`, так что игра
связывает звук с нужным геймпадом. Пятый и следующие геймпады, а также DualSense, подключённый
кабелем, работают через прежний режим (`uhid`, `dualsense_bridge.py`): без звука игр, с фильтрацией
вредных команд. Если виртуальную шину создать не удаётся, плагин тоже использует этот режим.

## Что плагин меняет в системе

| Что | Где | Когда убирается |
|---|---|---|
| Правило udev, скрывающее исходный Bluetooth-контроллер от Steam | `/etc/udev/rules.d/72-decky-dualsense-wired.rules` | при выключении эмуляции и выгрузке плагина |
| Модули ядра `dummy_hcd`, `libcomposite`, `usb_f_hid`, `usb_f_ss_lb`, `usb_f_uac2` | загружаются при создании виртуального контроллера | остаются загруженными до перезагрузки |
| Выход PipeWire `dualsense_gadget_<порт>` | сеанс пользователя `deck` | вместе с виртуальным контроллером |
| Источник PipeWire `dualsense_mic_<порт>` и канал `/run/user/<uid>/dualsense_mic_<порт>.fifo` | сеанс пользователя `deck` | при выключении микрофона |
| Драйвер `hid-generic` вместо `hid-playstation` у Bluetooth-геймпада (на время привязки ненадолго включается `ignore_special_drivers` ядра) | `/sys/bus/hid` | при выключении микрофона, эмуляции и выгрузке плагина |
| Служба `DualSenseWiredHelper` и файл `dualsense_wired_helper.exe` | каждый префикс `steamapps/compatdata/*/pfx` | при удалении плагина (запущенные в этот момент префиксы пропускаются) |

Изменения реестра префикса вносятся только когда префикс не запущен, с сохранением владельца файла.

## Ограничения

- Звук игр и HD-вибрация — для четырёх геймпадов одновременно; с несколькими геймпадами
  сразу это пока не проверялось на практике (только с одним).
- Пока микрофон включён, к Bluetooth-геймпаду вместо драйвера `hid-playstation` подключается
  `hid-generic`: `hid-playstation` принимает голосовые пакеты за нажатия кнопки mute. При
  переключении микрофона геймпад один раз переподключается (игры этого не замечают).
- Игре, установленной впервые, нужен один запуск, чтобы появился её префикс; звук контроллера
  заработает со второго запуска.
- Некоторые игры используют DualSense только как контроллер XInput (так ведёт себя, например,
  Hogwarts Legacy — и на ПК тоже); в них функций DualSense нет.
- Значка заряда геймпада в верхней строке Steam нет (см. «Возможности»).

## Сборка

Нужны Node.js 16.14+ и pnpm v9:

```bash
pnpm i
pnpm run build
```

Служба для префиксов (`bin/dualsense_wired_helper.exe`) собирается компилятором zig
(`python -m pip install ziglang`):

```bash
python -m ziglang cc -target x86_64-windows-gnu -O2 -s -municode \
  -o bin/dualsense_wired_helper.exe native/helper/dualsense_wired_helper.c -lole32 -ladvapi32
```

## Отправка на Steam Deck по SSH (Windows)

На Deck один раз: задать пароль (`passwd`) и включить SSH (`sudo systemctl enable --now sshd`).

```powershell
./deploy.ps1 -Setup -DeckHost <ip-адрес-deck>   # один раз: SSH-ключ и помощник установки на Deck
./deploy.ps1                                    # собрать и залить; Decky перезагрузит плагин сам
./deploy.ps1 -Logs                              # смотреть лог плагина
./deploy.ps1 -Zip                               # только собрать out/<name>-v<version>.zip
```

Адрес Deck сохраняется в `deck.json` (в git не попадает), ключ — в `~/.ssh/steamdeck_ed25519`.
Перезагрузка плагина пересоздаёт виртуальный контроллер — во время игры её лучше не делать.

## Инструменты для исследований

`py_modules/dualsense_audio.py` — утилита командной строки (на Deck запускается от root):
`info`, `haptics`, `tone`, `stream [--source system|controller]`, `buttons`, `inputcheck`, `levels`,
`routing` (слуховой тест выбора динамик/наушники),
`gadget` (эксперимент с виртуальным контроллером при приостановленном плагине), `gadget-stop`.
`native/cfgmgr32` — прототип замены `CM_Get_Parent` для Wine (`python native/cfgmgr32/build.py`)
и утилиты `devtree.c` / `dsinfo.c` для сравнения дерева устройств Wine и Windows
(`python -m ziglang cc -target x86_64-windows-gnu -municode <файл>.c -lcfgmgr32 -lsetupapi -lole32 -lpropsys`). Результаты исследования протокола — в
`../research/FINDINGS.md`.
